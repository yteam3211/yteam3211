Commands: The Robot's Instructions

If Subsystems are the body parts, Commands are the brain or the instructions. A command tells a subsystem exactly what to do and for how long.

The Lifecycle of a Command

Every command follows a specific state machine. When a command runs, WPILib calls these four methods:

  1. initialize(): Called once when the command starts. Use this to reset sensors or set initial states.
  2. execute(): Called repeatedly every 20ms while the command is running. This is where you tell the motors to move.
  3. isFinished(): A true or false check. If it returns true, the command stops.
  4. end(boolean interrupted): Called once when the command stops. Use this to turn off motors for safety.

Examples of Commands

  • InstantCommand: A quick action like opening a claw. It starts, does the action, and ends immediately.
  • RunCommand: A continuous action like driving with a joystick. It runs until the match ends or it is interrupted.
  • SequentialCommandGroup: A list of commands to run one after another, such as raise arm and then open claw.

Requirements

When you create a command, you must tell it which Subsystems it needs.

If a DriveForward command is running, and you start a TeleopDrive command, WPILib will automatically stop the first one because they both require the DriveTrain subsystem. This prevents motors from getting conflicting instructions.

Summary

  • Subsystem: I am the arm. I have a motor. I can move up or down.
  • Command: I want the arm to move up for 2 seconds and then stop.
