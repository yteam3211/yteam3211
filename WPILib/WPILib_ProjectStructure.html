WPILib Project Structure

A robot project is not just random Java files. WPILib projects have a predictable shape so every programmer can find the robot startup code, subsystems, commands, constants, and vendor configuration.

The Files You Should Recognize

  • Robot.java: The timed robot lifecycle. Most teams keep this small.
  • RobotContainer.java: Where subsystems, commands, button bindings, and auto chooser setup are connected.
  • Constants.java: IDs, gear ratios, physical measurements, and tuning values.
  • subsystems/: Classes that own hardware like motors and sensors.
  • commands/: Classes that tell subsystems what to do.

Rule Of Thumb

If a class talks directly to motors or sensors, it probably belongs in a subsystem. If a class describes an action over time, it is probably a command.

src/main/java/frc/robot/
  Robot.java
  RobotContainer.java
  Constants.java
  subsystems/
    DriveSubsystem.java
  commands/
    ArcadeDriveCommand.java

Mission

Create a new command-based robot project and identify where you would put a drivetrain, shooter, and arm. You do not need to write the subsystem yet; just make sure the folder structure makes sense.
