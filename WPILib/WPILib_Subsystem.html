Subsystems: The Robot's Body Parts

In the Command-Based framework, a Subsystem represents a physical mechanism of the robot. Think of it as a body part that knows how to perform its own basic functions.

What is a Subsystem?

A Subsystem is a Java class that encapsulates hardware. For example, if your robot has a claw, you create a ClawSubsystem.

Inside this class, you define:

  1. Hardware: The motor controllers, solenoids, and sensors that belong to that mechanism.
  2. Methods: Simple functions that make the hardware do something, such as openClaw(), closeClaw(), or getArmAngle().

The Gold Rule of Subsystems

Subsystems should be dumb. A subsystem should not decide when to move or how fast to move based on logic. It should only provide the ability to move. The intelligence belongs in the Commands.

Example: An Intake Subsystem

If we have an intake with one motor, the subsystem would look like this conceptually:

  • Hardware: TalonFX intakeMotor
  • Method 1: setSpeed(double speed) sets the motor to a specific percent output.
  • Method 2: stop() sets the motor to 0.

Why use Subsystems?

  • Organization: It keeps all the code for one mechanism in one file.
  • Safety: It prevents two different parts of the code from trying to control the same motor at the same time using a system called requirements.
