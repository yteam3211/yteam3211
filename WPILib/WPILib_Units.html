WPILib Units

Robot code uses a lot of measurements: angles, distances, speeds, voltages, currents, and times. WPILib's units system lets Java carry the type of measurement with the value, so students are less likely to mix up degrees and radians, meters and inches, or volts and amps.

The short version is: a Unit describes the measurement system, and a measure like Angle, Voltage, or Current stores a number with that unit.

1. Importing Units

Most robot code imports WPILib's predefined units statically. This makes code read naturally.

import static edu.wpi.first.units.Units.*;

import edu.wpi.first.units.measure.Angle;
import edu.wpi.first.units.measure.AngularVelocity;
import edu.wpi.first.units.measure.Current;
import edu.wpi.first.units.measure.Distance;
import edu.wpi.first.units.measure.LinearVelocity;
import edu.wpi.first.units.measure.Time;
import edu.wpi.first.units.measure.Voltage;

What this means: Units contains names like Degrees, Radians, Volts, Amps, Meters, and Seconds. The measure interfaces describe the kind of value you are storing.

2. Creating Measurements

Use of to create a measurement. The unit name decides what the number means.

Angle armGoal = Degrees.of(45.0);
AngularVelocity shooterSpeed = RPM.of(3500.0);
Voltage motorVoltage = Volts.of(6.0);
Current motorCurrent = Amps.of(32.0);
Distance elevatorHeight = Meters.of(0.75);
Time timeout = Seconds.of(1.5);

What each one means:

  • Degrees.of(45.0) creates an Angle.
  • RPM.of(3500.0) creates an AngularVelocity.
  • Volts.of(6.0) creates a Voltage.
  • Amps.of(32.0) creates a Current.
  • Meters.of(0.75) creates a Distance.
  • Seconds.of(1.5) creates a Time.

3. Converting Back To Numbers

Most WPILib and vendor APIs still want plain double values. Use in when you need to convert a typed measurement into a number.

Angle armGoal = Degrees.of(90.0);

double goalDegrees = armGoal.in(Degrees);
double goalRadians = armGoal.in(Radians);

Why this helps: goalDegrees and goalRadians are different numbers, but they represent the same angle. The conversion is explicit, so the code says exactly what unit the hardware or controller expects.

4. Angle And Angular Velocity

Arms, wrists, and swerve modules usually care about angle. Flywheels and shooter wheels usually care about angular velocity.

Angle wristSetpoint = Degrees.of(30.0);
AngularVelocity shooterSetpoint = RotationsPerSecond.of(60.0);

double wristRadians = wristSetpoint.in(Radians);
double shooterRadPerSec = shooterSetpoint.in(RadiansPerSecond);
double shooterRpm = shooterSetpoint.in(RPM);

Common mistake: many math functions expect radians, but humans often tune in degrees. Store the value as an Angle, then convert at the exact place that needs radians.

5. Voltage And Current

Voltage is what we command to motors. Current is what the motor is drawing. They are not the same thing, and the units system makes that difference visible.

Voltage requestedVoltage = Volts.of(8.0);
Current statorCurrent = Amps.of(38.0);

motor.setVoltage(requestedVoltage.in(Volts));

if (statorCurrent.gt(Amps.of(60.0))) {
    stopMotor();
}

How to think about it: command volts, measure amps. A current spike often means a mechanism is jammed, stalled, or hitting a hard stop.

6. Distance And Linear Velocity

Elevators and drivetrains usually use linear units. Use Distance for positions and LinearVelocity for speeds.

Distance elevatorGoal = Inches.of(24.0);
LinearVelocity driveSpeed = MetersPerSecond.of(2.0);

double elevatorMeters = elevatorGoal.in(Meters);
double driveMetersPerSecond = driveSpeed.in(MetersPerSecond);

Why this helps: a team can talk about an elevator in inches, while the simulation and WPILib math use meters internally.

7. When To Use Raw Doubles

  • Use typed units in subsystem methods, constants, commands, and important setpoints.
  • Use raw doubles when a library method requires a double.
  • Convert close to the hardware boundary, not far away in command code.
  • Put the unit in the variable name when using a raw double.
